Where these icons come from, and the terms

Every icon in this library is an official Databricks SVG file. Nothing is redrawn, traced or approximated. The files come from Databricks URLs. These are the named product marks and the Lava line-icon set on databricks.com. The icons/sources/ directory holds each original file next to a manifest that gives its source URL. Two marks are different: Apache Spark and Apache Iceberg are project logos of the Apache Software Foundation.

What the build changes

The build applies four mechanical transforms and makes no other change. It fits each source file into a padded 48×48 canvas and keeps the aspect ratio. It adds the product slug to each internal id, each url(#…) reference and each CSS class. Then icons can share a page, and their gradients and clip paths do not collide.

The build also recolors the mono and tile variants. It keeps the three Databricks color roles separate: foreground, light tint and white plate. If it joins these roles, a mark becomes a blob. Last, it removes a full-bleed white background plate, because such a plate looks like an opaque box on a dark diagram. The svg/ directory holds the published artwork with the fit step and the namespace step only.

Color and type

The category colors are exact values from the Databricks primary palette and extended palette. This page uses DM Sans and DM Mono on the 8px type scale from the guidelines. Databricks gives this purpose for the extended palette: “a functional need for additional shades of color to enhance the comprehension of a message or to provide additional clarity through visual hierarchy”. A color code on a diagram layer has this purpose. The build calculates the contrast of the white glyph on each tile. If one value is less than 3:1, the build fails.

A label on a Databricks product in a technical diagram is a descriptive use. Before you use these assets commercially or in public material, read the brand guidelines and speak to Databricks.

The product names, the descriptions and the groups come from research on databricks.com and docs.databricks.com. They show the published information at build time. Databricks changes product names often. Make sure that a name is current before you publish a diagram. The README explains how to add a product to this set.
